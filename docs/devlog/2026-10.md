## 2026-10-15 - Stop requiring the retired agent-docs tool

### Result

- The Linux installer, installed launcher, and CI verification scripts no
  longer copy the runtime-kit agent-docs catalog or pass the agent-docs home
  and state variables. They pass the authenticated agent-docs executable only
  when the selected runtime-kit's nils declaration lists it.
- The release envelope verifier accepts a nils-cli tool set with or without
  agent-docs, as declared by the pinned runtime-kit, instead of exactly seven
  tools.

### Why / context

- nils-cli retires agent-docs; runtime-kit owns its activated documents and its
  owner launcher sets its own document paths, so the Workbench copy was unused.
- Removing the executable entirely waits until the pin advances to a
  runtime-kit release that no longer declares agent-docs.
- Launch configurations written by older installs still carry agentDocsHome and
  agentDocsBin; the launcher ignores them, and an older install's agent-docs
  directory is left in place.

### Evidence

- The first revision dropped the executable as well; the Combined DSH profile
  owner install then failed runtime-kit setup with activation-health-failed,
  because the pinned runtime-kit still declares agent-docs and probes it.
- Unit tests cover six- and seven-tool selections for setup and launch, and
  launch configurations from older installs; the Linux release, installer, and
  owner-install gates run in CI.

## 2026-10-06 - Add a ref guard to the combined-profile workflow definition

### Result

- The combined-profile workflow definition on `main` skips
  `workflow_dispatch` jobs unless the selected ref is `refs/heads/main`.
  Older refs that still carry the earlier definition are outside this change.
  The installer timeout fixture passes its marker path as a process argument.

### Why / context

- CodeQL reported cache-poisoning alerts on authenticated workflow steps. This
  change adds a job-level ref condition to the workflow definition on `main`;
  it does not change the behavior of older refs that retain the earlier
  definition. The separate review-thread disposition finds the automated HIGH
  cache-poisoning premise unsubstantiated by this workflow's configuration and
  documented cache scopes.

  pnpm install --frozen-lockfile --strict-peer-dependencies; pnpm
  web:metadata:check; pnpm web:build; pnpm typecheck; pnpm test (160 tests, 159
  passed, 1 skipped); bash scripts/check-publication.sh.
